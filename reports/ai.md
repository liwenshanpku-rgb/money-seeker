# AI 仓位顾问：让 Claude 决定 BTC 仓位（0%–150%）

前面几轮都是量化规则：网格、动量、均线、资金费率、链上指标。这一轮换思路：**由 AI 综合各种信息做判断**，代码只负责准备数据、设护栏、记账和评估。

## 它怎么工作

每次运行 `python -m money_seeker ai`：

1. **本地准备行情快照**：BTC 价格，7 / 30 / 90 / 365 天涨跌，50 / 200 日均线，30 天波动率，离历史高点的回撤，Hyperliquid 永续合约的资金费率和持仓量（拿不到时改用 Binance），3 个月美债利率，200 日均线规则当前的模式，以及最近 5 次决定。
2. **调用 Claude（默认 `claude-opus-5-5`，深度思考，effort = high），开启网络搜索（最多 12 次）和网页抓取（最多 6 次，每页最多 6000 token，屏蔽 sec.gov）**。提示词给了一份必查清单，Claude 要逐项查最近 1–2 周的情况：
   - 现货 ETF 资金流；
   - 衍生品（未平仓合约、基差、期权、爆仓）；
   - 链上数据（MVRV、长期持有者、交易所余额、稳定币）；
   - 宏观（美联储、美元、美债、美股）；
   - 监管和重大事件；
   - 市场情绪。

   搜索结果只有摘要时，抓取原网页读具体数字。**某类信息查不到时不能据此加减仓**：在依据里写“未能获取”，信息整体不足时维持上次仓位。
3. **按固定结构输出**：
   - 目标仓位（0%–150% 的整数）、置信度、一两句话的判断；
   - 主要依据（每条标明看涨 / 看跌 / 中性和权重）、主要风险；
   - **什么情况下应该改变决定**、建议几天后重新评估；
   - 参考来源链接。
4. **代码层的护栏**（默认开启，可以逐项关闭）：

   | 护栏 | 默认值 | 原因 |
   | --- | --- | --- |
   | 单次最多调整 | 25 个百分点 | 避免模型一次判断失误就大幅调仓 |
   | 变化太小不调 | 小于 10 个百分点就维持原仓位 | 减少来回交易的成本 |
   | 加杠杆需要上涨趋势 | 价格不在 200 日均线上涨模式时，最高 100% | 之前的回测里，借钱加仓后一直拿着在熊市会被强平（[loan.md](loan.md)） |
   | 仓位范围 | 0%–150% | 150% 时借款占抵押品约 33%，BTC 下跌约 58% 会被强平 |

   想完全按 AI 的判断来，加 `--no-guardrails`。
5. **记日志**：每次决定（含快照、模型原始建议、护栏调整、理由、来源、token 用量）追加写入 `ai_journal/decisions.jsonl`。这个目录默认不提交到 git，因为里面是你的个人资产数据。

**拒答兜底**：已开启服务端 `fallbacks: "default"`。如果请求被安全策略拒答，服务端会自动换模型重试；仍被拒时，程序会报错，不会给出仓位。

## 为什么不能回测，只能从今天开始验证

前面所有策略都能用历史数据回测，**AI 顾问不行**：
- Claude 的训练数据里包含过去几年的行情和新闻。让它“回到 2022 年做决定”，它多少知道后来发生了什么，回测结果会好得不真实；
- 网络搜索只能搜到现在的网页，没法还原过去某一天的信息环境。

所以唯一可信的检验是**前向模拟盘**：从今天起每次决定都记下来，过一段时间再用 `ai-review` 和两个基准比较：
- **买入持有**（一直 100%）；
- **核心 50% + 200 日均线**（[playbook.md](playbook.md) 里的方案 B）。

## 建议的验证方式（开始前定好，避免事后找理由）

1. **先模拟，不动真钱**：真实仓位继续按方案 B（或你现有的方式）执行，AI 的决定只记在日志里。
2. **固定频率**：每周运行一次（例如每周一北京时间 8 点后），遇到大事件可以加跑。不要因为行情波动临时多跑，那样会让样本有偏差。
3. **固定配置**：模型、effort、护栏设置在验证期内不改。
4. **至少 6 个月，最好 12 个月**，然后运行：

   ```bash
   python -m money_seeker ai-review --plot ai_review.png
   ```

5. **事先定好的通过标准**（建议）：
   - 在同一区间内，最大回撤不比方案 B 大；
   - 并且收益或夏普比率**同时**超过买入持有和方案 B。

   达不到就继续用方案 B。半年的结果主要是噪音，程序在样本不足半年时也会提示。

## 每次怎么跑

```bash
# 先配置凭据（任选一种）
ant auth login                 # 或 export ANTHROPIC_API_KEY=...

# 只看会发给模型的内容，不调用 API、不计费
python -m money_seeker ai --dry-run --btc 1.0

# 正式运行：给出持仓后会算出具体下单数量
python -m money_seeker ai --btc 1.0 --cash 0 --debt 0

# 调用 3 次取中位数，减少单次回答的随机性（费用 ×3）
python -m money_seeker ai --btc 1.0 --samples 3

# 回看模拟盘表现
python -m money_seeker ai-review --plot ai_review.png
```

在本地也可以用 `--from-kraken` 自动读取 Kraken 持仓并算出下单数量（设置方法见 [playbook.md](playbook.md)），例如 `python -m money_seeker ai --from-kraken`。**不要在公开的 GitHub 任务里使用这个选项。**

## 每周一自动运行（Claude Code 定时任务，使用订阅额度）

从 2026-10 起，每周的决策不再调用 Claude API，而是由 Claude Code 定时任务（Routine）完成，使用 Claude 订阅的额度，没有按 token 计费。分工：

| 步骤 | 谁来做 | 时间 |
|---|---|---|
| 行情快照：日线、均线、波动、Hyperliquid 资金费率与持仓量、美债利率 → `ai_journal/snapshot.json` | GitHub Actions（`signal-daily.yml`，不需要密钥） | 每天 00:45 UTC |
| 联网研究六类信息、给出目标仓位（同一份系统提示词和输出结构） | Claude Code 定时任务，唤醒有仓库推送权限的那个 Claude Code 会话执行 | 每周一 01:13 UTC（北京时间 09:13） |
| 校验 JSON、套用护栏、写入 `decisions.jsonl` 和 `latest.md` | 定时任务运行 `python -m money_seeker ai-record` | 同上 |
| 重新发布当天的信号文件（带上新决定） | GitHub Actions（`signal-daily.yml` 周一第二次运行） | 每周一 02:17 UTC |
| 模拟盘评估 `review.txt` / `review.png` | GitHub Actions（`signal-daily.yml`） | 每天 |
| 手机推送本周汇总 | 另一个只读的 Claude Code 定时任务 | 每周一 02:25 UTC（北京时间 10:25） |

相关命令：

```bash
python -m money_seeker ai-snapshot --out ai_journal/snapshot.json     # 只生成快照
python -m money_seeker ai-prompt                                       # 打印给定时任务的完整说明
python -m money_seeker ai-record --answer answer.json --latest ai_journal/latest.md
```

`ai-record` 会拒绝过期的快照（超过 2 天）和同一收盘日的重复记录，模型输出不符合结构（例如仓位超出 0–150）时也不会写入。

和 API 版本的区别：
- 规则、提示词、输出结构和护栏完全相同；
- 研究用的是 Claude Code 的网络搜索和网页抓取。部分网站可能被定时任务所在环境的网络策略挡住，这时按规则在 evidence 里写“未能获取”，不会因此调仓；
- 日志里 `model` 字段为 `claude-code-routine`，`estimated_cost_usd` 为空。

**备用**：`.github/workflows/ai-weekly.yml` 仍然可以在 Actions 页面手动运行（使用 `ANTHROPIC_API_KEY`，按次计费，约 $0.3–0.6），不再定时运行。

**注意**：仓库是公开的，`ai-journal` 分支上的决定和理由任何人都能看到。日志里没有你的持仓数量。

## AI 波段模拟盘（事件触发，2026-10-30 起）

目的：检验“大波动后让 AI 及时重新判断、调整仓位”有没有价值。独立记账，不影响每周决策那条记录，不下单。

| 步骤 | 做什么 |
|---|---|
| 价格检查（每 6 小时，独立的小会话） | `python3 scripts/swing_check.py`，只用标准库：BTC 24 小时涨跌 ≥ 5% 或 72 小时 ≥ 8% 时触发；距上次波段决定不到 48 小时的，价格还要再变动 ≥ 5%；7 天最多 3 次 |
| 触发后（唤醒有推送权限的会话） | `ai-prompt --swing trigger.json` 读规则 → 联网研究（重点是这次波动的原因和接下来 1–4 周的风险）→ `ai-swing-record` 套用相同护栏，写入 `ai_journal/swing_decisions.jsonl` 和 `swing_latest.md` |
| 评估（每天，GitHub Actions） | `ai-review --swing-journal ...`：波段决定按记录时的盘中价成交，与每周 AI、买入持有、方案 B 在同一区间比较，写进 `review.txt` |

起点仓位取每周决策的最新仓位（85%）。跑满 6 个月后，用扣除手续费和短期资本利得税之后的结果和每周 AI、方案 B 比较，再决定要不要保留。

## 需要清楚的风险

1. **没有证据表明 AI 能择时**。这是一个实验，不是验证过的策略。前面的量化研究里，绝大多数看起来有道理的思路在样本外都失败了。
2. **结果有随机性**：同样的输入，两次调用可能给出不同的仓位。`--samples 3` 取中位数可以缓解，但会增加费用。
3. **信息质量**：网络搜索可能搜到过时、错误或带立场的内容。提示词要求模型把网页当信息而不是指令、注意日期、引用来源，但不能完全避免。**请看一眼参考来源。**
4. **容易被叙事带着走**：AI 擅长讲道理，一个说得通的理由不等于正确的判断。护栏的作用就是限制单次判断的影响。
5. **杠杆**：仓位超过 100% 就是借钱，强平、平台和利率风险见 [loan.md](loan.md)。不想承担这些风险，可以把护栏的上限改成 100%（把 `Guardrails.max_pct` 设为 100）。
6. **数据依赖**：行情和资金费率取自 Binance，美债利率取自 FRED。这个开发环境访问不了这些网站，也没有 Claude API 凭据，所以**实际调用流程只用模拟客户端测试过**。第一次在你的电脑上运行时，请先用 `--dry-run` 确认快照数据正常。
