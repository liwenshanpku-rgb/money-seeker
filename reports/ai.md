# AI 仓位顾问：让 Claude 决定 BTC 仓位（0%–150%）

前面几轮都是量化规则：网格、动量、均线、资金费率、链上指标。这一轮换思路：**由 AI 综合各种信息做判断**，代码只负责准备数据、设护栏、记账和评估。

## 它怎么工作

每次运行 `python -m money_seeker ai`：

1. **本地准备行情快照**：BTC 价格，7 / 30 / 90 / 365 天涨跌，50 / 200 日均线，30 天波动率，离历史高点的回撤，Binance 资金费率，3 个月美债利率，200 日均线规则当前的模式，以及最近 5 次决定。
2. **调用 Claude（默认 `claude-opus-5-5`，深度思考，effort = high）并开启网络搜索**。Claude 自己去查最近 1–2 周的信息：价格结构、现货 ETF 资金流、衍生品持仓、链上数据、宏观（利率、美元、流动性）、监管和新闻、市场情绪。
3. **按固定结构输出**：
   - 目标仓位（0%–150% 的整数）、置信度、一两句话的判断；
   - 主要依据（每条标明看涨 / 看跌 / 中性和权重）、主要风险；
   - **什么情况下应该改变决定**、建议几天后重新评估；
   - 参考来源链接。
4. **代码层的护栏**（默认开启，可以逐项关闭）：

   | 护栏 | 默认值 | 原因 |
   | --- | --- | --- |
   | 单次最多调整 | 25 个百分点 | 避免模型一次判断失误就大幅调仓 |
   | 变化太小不调 | 小于 10 个百分点就维持原仓位 | 减少来回交易的成本 |
   | 加杠杆需要上涨趋势 | 价格不在 200 日均线上涨模式时，最高 100% | 之前的回测里，借钱加仓后一直拿着在熊市会被强平（[loan.md](loan.md)） |
   | 仓位范围 | 0%–150% | 150% 时借款占抵押品约 33%，BTC 下跌约 58% 会被强平 |

   想完全按 AI 的判断来，加 `--no-guardrails`。
5. **记日志**：每次决定（含快照、模型原始建议、护栏调整、理由、来源、token 用量）追加写入 `ai_journal/decisions.jsonl`。这个目录默认不提交到 git，因为里面是你的个人资产数据。

**拒答兜底**：已开启服务端 `fallbacks: "default"`。如果请求被安全策略拒答，服务端会自动换模型重试；仍被拒时，程序会报错，不会给出仓位。

## 为什么不能回测，只能从今天开始验证

前面所有策略都能用历史数据回测，**AI 顾问不行**：
- Claude 的训练数据里包含过去几年的行情和新闻。让它“回到 2022 年做决定”，它多少知道后来发生了什么，回测结果会好得不真实；
- 网络搜索只能搜到现在的网页，没法还原过去某一天的信息环境。

所以唯一可信的检验是**前向模拟盘**：从今天起每次决定都记下来，过一段时间再用 `ai-review` 和两个基准比较：
- **买入持有**（一直 100%）；
- **核心 50% + 200 日均线**（[playbook.md](playbook.md) 里的方案 B）。

## 建议的验证方式（开始前定好，避免事后找理由）

1. **先模拟，不动真钱**：真实仓位继续按方案 B（或你现有的方式）执行，AI 的决定只记在日志里。
2. **固定频率**：每周运行一次（例如每周一北京时间 8 点后），遇到大事件可以加跑。不要因为行情波动临时多跑，那样会让样本有偏差。
3. **固定配置**：模型、effort、护栏设置在验证期内不改。
4. **至少 6 个月，最好 12 个月**，然后运行：

   ```bash
   python -m money_seeker ai-review --plot ai_review.png
   ```

5. **事先定好的通过标准**（建议）：
   - 在同一区间内，最大回撤不比方案 B 大；
   - 并且收益或夏普比率**同时**超过买入持有和方案 B。

   达不到就继续用方案 B。半年的结果主要是噪音，程序在样本不足半年时也会提示。

## 每次怎么跑

```bash
# 先配置凭据（任选一种）
ant auth login                 # 或 export ANTHROPIC_API_KEY=...

# 只看会发给模型的内容，不调用 API、不计费
python -m money_seeker ai --dry-run --btc 1.0

# 正式运行：给出持仓后会算出具体下单数量
python -m money_seeker ai --btc 1.0 --cash 0 --debt 0

# 调用 3 次取中位数，减少单次回答的随机性（费用 ×3）
python -m money_seeker ai --btc 1.0 --samples 3

# 回看模拟盘表现
python -m money_seeker ai-review --plot ai_review.png
```

输出示例结构（具体内容由模型生成）：

```
日期: 2026-10-19   BTC: ...   趋势规则: UP
模型建议仓位: 110%（采样 [110]）   置信度: medium
执行仓位: 110%（上次 100%）
判断: ...
主要依据:
  [bullish/high] 现货 ETF 资金流：...
  [bearish/medium] 宏观：...
主要风险: ...
改变决定的条件: ...
建议 7 天后重新评估
护栏调整: ...
操作:
  BTC +0.100000（目标 1.100000）
  借款 +8,200 USD（目标 8,200，借款后 LTV 9%）
参考来源: ...
```

**费用（粗略估计）**：每次调用包含搜索结果，输入约 2–6 万 token，加上思考和输出几千到一万多 token，再加最多 8 次网络搜索。按 Claude Opus 5.5 的价格（输入 $4 / 百万 token，输出 $20 / 百万 token），每次大约 **$0.3–0.6**。每周一次每月约 $2–3；每天一次约 $10–20；`--samples 3` 再乘以 3。以实际账单为准，每次的 token 用量都记在日志里。

## 需要清楚的风险

1. **没有证据表明 AI 能择时**。这是一个实验，不是验证过的策略。前面的量化研究里，绝大多数看起来有道理的思路在样本外都失败了。
2. **结果有随机性**：同样的输入，两次调用可能给出不同的仓位。`--samples 3` 取中位数可以缓解，但会增加费用。
3. **信息质量**：网络搜索可能搜到过时、错误或带立场的内容。提示词要求模型把网页当信息而不是指令、注意日期、引用来源，但不能完全避免。**请看一眼参考来源。**
4. **容易被叙事带着走**：AI 擅长讲道理，一个说得通的理由不等于正确的判断。护栏的作用就是限制单次判断的影响。
5. **杠杆**：仓位超过 100% 就是借钱，强平、平台和利率风险见 [loan.md](loan.md)。不想承担这些风险，可以把护栏的上限改成 100%（把 `Guardrails.max_pct` 设为 100）。
6. **数据依赖**：行情和资金费率取自 Binance，美债利率取自 FRED。这个开发环境访问不了这些网站，也没有 Claude API 凭据，所以**实际调用流程只用模拟客户端测试过**。第一次在你的电脑上运行时，请先用 `--dry-run` 确认快照数据正常。

## 代码

- `money_seeker/ai_advisor.py`：行情快照、提示词、Claude 调用（网络搜索 + 结构化输出 + `pause_turn` 续接 + 拒答兜底）、护栏、日志、下单换算、模拟盘评估；
- 命令：`python -m money_seeker ai`、`python -m money_seeker ai-review`；
- 测试：`tests/test_ai_advisor.py`（用模拟的 Claude 客户端，不会调用真实 API）。
