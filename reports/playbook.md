# BTC 持仓操作手册

本手册把前面几轮研究的结论（[btc.md](btc.md)、[loan.md](loan.md)）整理成每天可以照着做的流程。
数字截至 2026-10-12。本手册不构成投资建议，执行前请确认自己理解并能承受其中的风险。

---

## 一、三种方案对比

| 方案 | 规则 |
| --- | --- |
| **A. 买入持有** | 一直 100% 持有 BTC，什么都不做 |
| **B. 核心 + 趋势** | 50% 永远持有；另外 50% 在 BTC 处于上涨模式时持有，下跌模式时卖出换成美债 |
| **C. 核心 + 趋势 + 上涨时借款** | 在 B 的基础上，上涨模式时以 BTC 作抵押，借入“核心价值 × 50%”的稳定币买 BTC；进入下跌模式时先还清借款 |

**上涨 / 下跌模式**：
- BTC 日收盘价**涨破 200 日均线 × 1.03** 时进入上涨模式；
- **跌破 200 日均线 × 0.97** 时进入下跌模式；
- 两条线之间维持原来的模式。

| | A 买入持有 | B 核心 + 趋势 | C 核心 + 趋势 + 借款（年利率 10.5%） |
| --- | --- | --- | --- |
| **2014-06 起** 年化 | 48.7% | 57.6% | **62.7%** |
| 　最大回撤 | -84% | -74% | **-71%** |
| 　累计（倍数） | 130 倍 | 265 倍 | **391 倍** |
| **2022-01 起** 年化 | 12.3% | 20.2% | **24.2%** |
| 　最大回撤 | -67% | -40% | **-37%** |
| 　累计 | +72% | +136% | **+175%** |
| **2026 年初至今**（1/1 – 10/12） | -7.7% | **+2.0%** | +0.7% |
| 　最大回撤 | -40% | -21% | **-20%** |
| 每年调仓次数 | 0 | 约 3 次 | 约 3 次 |

**2026 年发生了什么**：
- BTC 从年初 $88.7k 跌到 6 月底 $58.4k，又涨回 10 月的 $81.8k；
- B、C 在 2025-11-03 已经进入下跌模式，上半年只拿着一半 BTC，跌幅少了一半；
- 2026-08-20 重新进入上涨模式，但这时价格已经从底部反弹了约 25%，所以 6–8 月的反弹只吃到一部分；
- C 在 8 月下旬加了杠杆后价格又回调了一次，今年反而略差于 B。

**怎么选**：
- **B 适合大多数人**：不借钱，没有强平和借贷平台风险，长期比 A 多赚、回撤更小。
- **C** 适合愿意承担借贷平台风险、并且能严格执行“下跌模式先还款”的人。长期每年再多约 5 个百分点，但有平台风险，熊市里也可能多一些操作压力。
- 两种方案的共同代价：**V 型反弹和持续上涨的牛市里会比 A 少赚**（2024 年以来 B 年化 21.7%，A 是 26.1%；2026 年夏天的反弹 B 只吃到 +22.5%，A 是 +39.6%）。

## 二、准备工作（一次性）

1. **账户**
   - **核心 BTC**：放硬件钱包或自己信任的托管处。方案 C 需要放进借贷平台作抵押，见下文。
   - **交易所账户**：用于买卖 BTC，例如 Binance、OKX、Coinbase 等，按所在地合规选择。
   - **现金停放处**：下跌模式时存放卖出所得。可选美债 ETF / 货币基金（证券账户）、代币化美债、或交易所的稳定币理财。按安全性和收益率自己权衡。
   - **方案 C 另需借贷渠道**：链上借贷平台（如 Aave，用 WBTC / cbBTC 作抵押，浮动利率）或中心化借贷平台（如 Ledn，固定利率 10% 左右）。先小额试用，熟悉抵押、借款、还款的流程。
2. **工具**
   - 安装本项目：`pip install -r requirements.txt`；
   - 确认能运行 `python -m money_seeker today`。它需要能访问 Binance；如果不能访问，用下文的 TradingView 手动方法。
3. **记录表**：准备一个表格记录每次调仓，模板见第八节。用于对账和报税。

## 三、开始执行（现在该怎么建仓）

截至 2026-10-12：

| | 数值 |
| --- | --- |
| BTC 收盘价 | $81,813 |
| 200 日均线 | $69,734 |
| 退出线（均线 × 0.97） | **$67,642** |
| 当前模式 | **上涨模式（自 2026-08-20 起）** |

所以现在开始执行的话，**目标仓位是上涨模式**：
- **方案 B**：100% 持有 BTC。如果你现在是全仓 BTC，什么都不用做，只需记下“核心 = 总净值的 50%”。
- **方案 C**：100% 持有 BTC，再以 BTC 作抵押，借入“总净值 × 25%”（即核心价值 × 50%）的稳定币买 BTC。借款后 LTV（负债 / 抵押品价值）约 20%。

**注意**：
- 进入上涨模式已经快两个月，价格比进入时高了约 12%。中途加杠杆的风险比在切换当天加更高。
- 对方案 C，可以先按 B 执行，**等下一次进入上涨模式的切换日再开始借款**。这是更稳妥的做法。

## 四、每天的流程（约 2 分钟）

**时间**：每天北京时间 **08:00 之后**。BTC 日线在 UTC 00:00（北京时间 08:00）收盘。

**第 1 步：运行检查**

```bash
# 方案 B
python -m money_seeker today --btc <持有的 BTC 总数> --cash <现金/美债 USD>

# 方案 C
python -m money_seeker today --btc <BTC 总数> --cash <现金 USD> --debt <借款余额 USD> --borrow 0.5
```

**第 2 步：看输出，分四种情况处理**

| 输出 | 做什么 |
| --- | --- |
| `操作: 无需交易` 且没有提醒 | 什么都不做（绝大多数日子都是这样） |
| `← 今天刚切换！` | 按输出里列出的下单数量，在 **24 小时内**完成调仓（见第五节） |
| `! LTV ... ≥ 35%`（仅方案 C） | 价格大跌但还没触发退出线。准备好还款资金，第二天再检查 |
| `! LTV ... ≥ 45%`（仅方案 C） | **当天还款**，把 LTV 降回 20% 左右（输出里有建议金额） |

**第 3 步**：如果有交易，记到记录表里。

**没法运行程序时的手动方法**：
- 在 TradingView 打开 `BINANCE:BTCUSDT` 日线图，添加 200 周期简单移动平均线（MA 200，按收盘价计算）；
- 看最近一根**已收盘**的日线：
  - 收盘价 > MA200 × 1.03 → 上涨模式；
  - 收盘价 < MA200 × 0.97 → 下跌模式；
  - 两者之间 → 维持原来的模式。
- 只有模式和昨天不同时才需要操作。

### 用 Kraken 自动读取持仓（只读）

不想每天手动输入 BTC 数量和现金，可以让程序直接读 Kraken 账户余额。

**1. 在 Kraken 创建只读 API 密钥**（一次性）：
- 登录 Kraken（Kraken Pro 网页版）→ 设置 → **API**（有的版本叫 Connections & API）→ **Create API key**；
- 名称随意，例如 `money-seeker-readonly`；
- 权限**只勾选 Funds（资金）下面的 “Query（查询）”**；Deposit、Withdraw、交易下单等**全部不勾**；
- 可选：限制 IP 为你家里的网络地址，设置到期时间；
- 创建后会显示 **API Key** 和 **Private Key（私钥）**。私钥只显示一次，复制保存到密码管理器。

**2. 在你的电脑上设置环境变量**（不要写进代码，不要发在聊天里，不要提交到仓库）：

```bash
# macOS / Linux：在运行命令的终端里执行（只对当前终端有效）
export KRAKEN_API_KEY='你的 API Key'
export KRAKEN_API_SECRET='你的 Private Key'
```

Windows PowerShell：`$env:KRAKEN_API_KEY='...'`、`$env:KRAKEN_API_SECRET='...'`。

**3. 使用**：

```bash
python -m money_seeker kraken                              # 查看余额和当前 BTC 仓位
python -m money_seeker today --from-kraken                 # 方案 B 的每日检查，自动带入持仓
python -m money_seeker today --from-kraken --borrow 0.5 --debt <借款余额>   # 方案 C
```

**说明**：
- BTC 包括现货和 Kraken 理财里的 BTC（余额代码带 `.F`、`.B` 等后缀的也算）。注意锁定质押的部分不能马上卖出；
- 现金包括 USD 和常见美元稳定币（USDT、USDC 等）；其他币种和欧元等单独列出，不计入仓位；
- 在别的平台的借款读不到，需要用 `--debt` 手动输入；
- 只读密钥无法下单或提币，就算泄露，别人也只能看到余额。但仍然要妥善保管；
- **不要把 Kraken 密钥放到 GitHub Secrets、也不要在每周的 GitHub 任务里使用**：仓库和运行日志都是公开的，余额会被所有人看到。每周的 AI 任务是模拟盘，按它自己的历史仓位计算，不需要你的真实持仓。

### 每日简报自动推送（本地运行 + Bark）

在你自己的电脑上每天运行一次 `python -m money_seeker brief`。它会读 Kraken 持仓、判断方案 B 的模式、取 AI 顾问的最新决定，算出两种方案各需要买卖多少，然后通过你自建的 Bark 推送到手机。只读，不下单。

**什么时候推送**（其余日子只写本地文件，不打扰）：

| 情况 | 推送方式 |
| --- | --- |
| 方案 B 当天切换上涨 / 下跌模式 | **紧急推送**（穿透专注模式），附具体买卖数量 |
| 借款 LTV ≥ 35% / 45% | **紧急推送** |
| AI 顾问出了新决定（通常每周一） | 普通推送，附相对当前持仓要买卖多少 |
| AI 决定超过 9 天没更新（每周任务可能失败了） | 普通推送 |
| 每周一 | 普通推送一次汇总 |

**一次性设置**：

1. 拉取代码并安装：
   ```bash
   git pull          # 或 git clone https://github.com/liwenshanpku-rgb/money-seeker
   python -m venv venv
   venv\Scripts\pip install -r requirements.txt        # Windows
   ./venv/bin/pip install -r requirements.txt           # macOS / Linux
   ```
2. 在项目根目录把 `.env.example` 复制成 `.env`，填上 Kraken 只读密钥，以及和 `pm-maker`、`schwab-bot` 相同的 `BARK_URL`、`BARK_DEVICE_KEY`。`.env` 已在 `.gitignore` 里，不会被提交。
3. 测试一次（会强制推送一条到手机）：
   ```bash
   python -m money_seeker brief --always-push
   ```
4. 设成每天自动运行。BTC 日线在 UTC 0 点收盘（北京时间 08:00），建议在收盘后 45 分钟左右运行。下面按北京时间写；如果电脑在别的时区，换算成当地时间：
   - **Windows**（任务计划程序）：
     ```bat
     schtasks /Create /TN "money-seeker-brief" /TR "\"<项目路径>\deploy\brief.bat\"" /SC DAILY /ST 08:45
     ```
     然后在“任务计划程序”里打开这个任务 → 设置 → 勾选“**如果过了计划开始时间，立即启动任务**”，这样电脑关机错过的那天，开机后会补跑一次。
   - **macOS / Linux**（cron，`crontab -e` 加一行）：
     ```
     45 8 * * * <项目路径>/deploy/brief.sh
     ```
   运行日志写在 `state/brief.log`。

**有借款时**（方案 C）：`deploy/brief.bat` / `brief.sh` 里的命令改成 `python -m money_seeker brief --borrow 0.5 --debt <借款余额>`。借款余额变化时记得更新。

**给其他本地程序用的信号文件** `state/latest_signal.json`（每次运行都会更新，只在本机）：

```json

  "ai": {"as_of_close_utc": "2026-10-19", "target_pct": 85, "confidence": "low", "age_days": 1,
```

## 五、切换日的操作清单

先算一下：**总净值 = BTC 市值 + 现金 − 借款**。`today` 命令会直接给出具体数量。

### 切换为上涨模式

**方案 B**：
1. 赎回美债 / 货币基金，换成 USDT / USDC；
2. 全部买成 BTC，目标是 100% BTC。

**方案 C**：
1. 同 B 的两步；
2. 把 BTC 存入借贷平台作抵押；
3. 借入“总净值 × 25%”的稳定币，确认借款后 LTV 约 20%；
4. 用借来的稳定币买 BTC，可以继续存入抵押，让 LTV 保持在 20% 左右；
5. 记下借款金额、利率、借款日。

### 切换为下跌模式

**方案 B**：
1. 卖出 BTC，直到 BTC 市值 = 总净值 × 50%；
2. 卖出所得买入美债 / 货币基金。

**方案 C**：
1. 卖出 BTC，直到 BTC 市值 = 总净值 × 50%；
2. **先还清全部借款（含利息）**，取回抵押的 BTC；
3. 剩余现金买入美债 / 货币基金；
4. 核心 BTC 可以转回自己的钱包。

**下单方式**：
- 用限价单，挂在接近市价的位置，比如比市价差 0.1%；
- 金额大时分几笔，在当天内完成；
- 回测假设在信号后 24 小时左右的收盘价成交，当天内完成即可，不必追求精确时点。

**核心仓位怎么算**：
- 回测里，每次切换时按“当时总净值 × 50%”重新计算核心仓位，所以核心 BTC 的数量会随每轮行情变化；
- 如果更习惯“永远不卖的固定 BTC 数量”，也可以固定核心数量，结果相差不大。

## 六、风控规则

1. **只在切换日调仓**，平时不因为涨跌、新闻或情绪手动加减仓。这是回测成立的前提。
2. **借款上限**（方案 C）：借款不超过核心价值的 50%，即借款时 LTV 约 20%。历史上最高 LTV 只到过 24%（2020-03-09），离强平线（80%）还很远。借款再多，安全余量会快速变小。
3. **下跌模式一定先还清借款**。熊市里不背负债，是方案 C 安全的关键。
4. **LTV 警戒线**：35% 准备还款，45% 立即还款，降回 20%。这两条线是额外的安全规则，回测里从未触发过。
5. **利率太高就不借**：借款利率高于约 12% 时，本轮上涨模式按方案 B 执行。这条也是额外规则，没有回测。
6. **平台分散**：交易所、借贷平台、现金停放处尽量不要集中在同一家。不把全部资产放在任何一个平台上。
7. **不加额外杠杆**：不用永续合约或期权替代以上操作。

## 九、常见情况

- **错过了切换日**：尽快按 `today` 的输出补做。如果价格已经回到另一侧，以当天的模式为准。
- **价格在线附近来回波动**：3% 缓冲区就是为此设计的。在两条线之间时什么都不做。历史上平均每年约 3 次切换，个别年份会更多。
- **交易所或借贷平台出问题**（暂停提币、异常插针）：优先保证能还款、能取回抵押品，宁可提前减仓。
- **出门旅行**：提前查看离切换线还有多远（`today` 输出里有）。如果离得近，可以提前设好条件单或请家人代为执行。
- **想改参数**（比如换成 150 日均线、改核心比例）：可以，但请在开始前定好，**不要边执行边改**。不同参数的历史表现见 [btc.md](btc.md)。

## 十、心理准备和局限

- **一年内大约一半的时间会跑输买入持有**，要拉长到 3 年才大约七成跑赢（[btc.md](btc.md) D 节）。
- **最难受的时候是 V 型反弹**：价格已经涨了 20–30%，规则还没让你买回来。2026 年 6–8 月就是这样。
- **最大回撤仍然很大**：B 历史上最深 -74%，C -71%。规则只能减轻下跌，不能消除下跌。
- **证据有限**：长期多出来的收益主要来自 2018、2022 两次熊市，样本只有 3–4 轮牛熊。未来的熊市如果以不同方式出现（例如单日暴跌后直接反弹），规则可能失效。
- **回测没有计入**：税、平台风险、借款利率的波动、日内插针。

本手册不构成投资建议。
